# 診断ロジックの特性テスト（T1・T2）

## 実行

リポジトリのルートで実行します。外部パッケージやインストール作業は不要です。

```sh
node --test tests/scoring.test.cjs
```

実行確認環境：Node.js v24.22.1。`node:test`、`node:assert/strict`、`node:vm` などの標準機能のみを使用します。

この追加はT1（仕様・期待値の固定）とT2（内部集計Unitテスト）だけです。
ブラウザE2E、3言語の実操作検証、CI、公開・デプロイ設定は追加していません。

## 固定する現在の仕様

実装上の根拠は `js/app.js` の `calculate()`、`beginResults()`、`finishResults()` です。
次の記述は現在の挙動を固定するもので、新しい判定規則の提案ではありません。

- 通常回答は8問、各問で異なる1〜3タイプを選択します。タイプは表示位置ではなく単語配列の添字に対応します。
- 各問の6点を選択数で等分します。1語なら6点、2語なら各3点、3語なら各2点です。
- 全8問が有効なら総和48点です。通常回答の加点は整数です。
- `solo` はそのタイプを単独選択した問の数です。追加点ではありません。
- `focus` はField 7・8で得た点の合計です。すでに総得点に含まれ、追加の重みではありません。
- 順位は `score` → `solo` → `focus` の降順です。後ろの指標は、それより前の指標がすべて同じ場合だけ使います。
- Field 7とField 8の間に優先順位はありません。同一問内の選択順も採点に影響しません。
- 首位と3指標すべてが一致するタイプだけが最終同点候補です。首位以外の同点は追加選択を発生させません。
- 首位が複数なら、その全候補からユーザーが1タイプを選びます。人数による分岐はありません。
- 最終選択は集計値・回答Map・元の順位を変更しません。
- 完全同点では、現在のタイプ列挙順と安定ソートによりType番号の昇順が残ります。
- 併記タイプは元の順位表で主結果を除いた最初のタイプです。0点でも併記されます。

採点関数は回答の妥当性を検証しません。次も修正せず現状として固定します。

| 内部状態 | 現在の結果 |
| --- | --- |
| Field 8だけ未回答、他7問はType 1単独 | Type 1は `(42,7,6)` |
| 全問未回答 | 全タイプ `(0,0,0)`、9者同点 |
| 1問4語 | 各1.5点、拒否しない |
| 同じ問・タイプの値を異なるMapキーで2件登録 | 2件とも集計し合計6点、単独選択には数えない |
| 問番号が -1、8、文字列 `'0'`、null | 集計対象外 |
| 有効な問番号でタイプが0または10 | `TypeError` |

これらの不正状態は通常画面からの到達を保証するものではありません。
48点という総和だけでは回答の妥当性を証明できません。

## 期待値の管理

`fixtures/scoring.cjs` は具体的な回答、全9タイプの `[score, solo, focus]`、
順位、首位同点集合、最終選択ごとの併記タイプをリテラルで保存します。
期待値を本体から自動生成・更新するスクリプトは設けていません。

代表的な計算根拠：

| Fixture | 固定値の根拠 |
| --- | --- |
| single | 8回の単独選択で48点・単独8回、最後の2問で12点 |
| score | 最初の6問でType 1〜3が各12点、最後の2問のType 4・5は各6点・単独1回・focus 6点。総得点を優先 |
| solo | Type 3は12点・単独2回・focus 0、Type 2は12点・単独1回・focus 6。単独回数を優先 |
| focus | Type 5と1は各9点・単独1回。Type 5だけfocus 3で優先 |
| tie2 | Type 1〜2が各24点・単独0回・focus 6 |
| tie3 | Type 1〜3が各16点・単独0回・focus 4 |
| tie4 | Type 1〜4が各9点・単独0回・focus 0。他は最大4点 |
| tie5 | Type 1〜5が各8点・単独0回・focus 2。他は各2点 |
| tie6 | Type 1〜6が各6点・単独0回・focus 0。他は各4点 |

2〜6者同点では候補全員の選択を個別にテストし、主結果・併記タイプ・全集計値・回答の不変性を確認します。
タイプ番号順そのものが同点候補の表示順として維持されることも確認します。

## S01〜S13との対応

| ID | 検証 |
| --- | --- |
| S01 | 各Type 1〜9の単独6点・solo 1 |
| S02・S03 | 2語各3点、3語各2点、soloは0 |
| S04 | 同一タイプ8問の固定期待値 `(48,8,12)` |
| S05 | 選択数の全6,561組合せの総和48点 |
| S06 | 得点がsolo・focusに優先 |
| S07・S09 | 同得点ならsolo優先。focusの優劣が逆でも維持 |
| S08 | 得点・soloが同じならfocus優先 |
| S10 | 全fixtureでField 7・8を交換し、指標・順位・同点集合・結果を確認 |
| S11 | 全fixtureで各問の選択順を1問ずつ全順列で変更し、指標・順位・同点集合を確認 |
| S12・S13 | 未回答あり・全問未回答の現挙動 |

**3⁸＝6,561は各問の選択数（1・2・3）の組合せであり、全回答パターンではありません。**
S05は各選択数の組合せについて代表的なタイプ集合を1つ使います。
合計点の不変条件を補足するテストであり、固定期待値との照合を代替しません。
6,561回の検証はランナー上では1テストと数えます。

## 観測フックと境界

`helpers/scoring-harness.cjs` は実際の `data.js` と `app.js` をNodeのVM内で実行します。
既存の初期化処理も実行し、採点・結果処理をテスト側で再実装しません。
IIFE終了直前に観測用参照をメモリ上で追加するだけで、本体ファイルには書き込みません。
既存の関数・文・比較式は置換しません。

終了マーカーがない・重複する・末尾でない場合は明示的に失敗します。
挿入後のフック存在確認、および観測部分だけを除くと元ソースに戻ることもテストします。

DOM代替は初期化・結果表示に必要な最小範囲です。ブラウザの描画、フォーカス、
本物のクリックイベント、disabled制約、画像保存、言語別の画面挙動を検証しません。
結果候補のコールバック実行は内部集計のテストであり、E2Eではありません。

T3を実施する場合は、DOM代替や観測フックに依存せず実HTMLを操作し、
`rotations`による表示順とタイプの対応、最大3語制限、未選択での遷移禁止、
戻って変更、再スタート、3言語の同等性を別途確認してください。
